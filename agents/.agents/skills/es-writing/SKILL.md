# ESライティング

`/yomiyasu` を使って文章を書いてください。ESの本文を書く、または直すときは、下の構成とチェックに沿って内容を組み立て、仕上げの文章は `/yomiyasu` に従って整えます。

## 手順

1. 素材を確認する。`basic_info.md`、`career_vision.md`、`episodes/` があれば先に読む。企業名、設問、文字数が不明なら、1つずつ質問する。事実や数字は創作しない。
2. 構成を決める。全体は PREP（結論、理由、具体例、結論）。エピソードは STAR（状況、課題、行動、結果）に、行動の背景にある価値観（Why）を加える。
3. 本文を書く。文章は `/yomiyasu` に従って整える。
4. 下のチェックで見直し、本文のあとに「面接で深掘りされそうな点」を1〜2点だけ添える。

## 企業が見る4つの基準

1. 再現性：その経験が仕事でも発揮できる論理になっているか。
2. 主体性と価値観：自分の意思で考え行動したか。なぜそうしたか（Why）が明確か。
3. カルチャーフィット：志向性が志望企業の求める人物像と合うか。
4. 論理性と伝達力：専門的な内容が、非エンジニアの人事にも伝わる平易な言葉になっているか。

## 書くうえでのポイント（身の丈）

- 自分の寄与を正確に切り出す。課題を見つけた人、決めた人、自分が提案した内容、実際に手を動かした範囲を分け、成果と因果を盛らない。
- 他者の存在を残す。教授や先輩、メンバーから受けた指摘と、それで考えを直した経緯は、学べる人であることの根拠になる。
- 就活用に整えた言葉（KPI、ボトルネック、巻き込み等）で飾らない。当時本当に考えていたことと、使う言葉が一致しているか確かめる。
- 志望動機は「野心は大きく、現在地は正確に」。次の3つを時間軸でつなぐ。
  1. 今までの経験から提供できる価値
  2. 現時点で足りない力
  3. 入社後に身につけ、将来提供したい価値
- 企業分析は言い切らない。「御社の課題は〇〇です」ではなく、「公開情報を拝見する限り、〇〇を重要なテーマと理解しています」と書く。
- 「成長したい」だけで終わらせない。入社直後から大きな価値を出せるとも書かない。
- 抽象的で無難な表現は、具体的なエピソードに置き換える。
- 面接で深掘りされて説明できない主張は書かない。AIで文章を磨くときは、自分の寄与を超えた表現がないかの確認に使う。

## 出力

- 本文
- 面接で深掘りされそうな点（1〜2点）
- 確認したいこと（あれば1〜2点）
